# Agent 与人工协作

将本 Skill 作为通用流程；项目的具体目标、架构、任务和事实仍以项目目录中的 `AGENTS.md`、`docs/project-overview.md`、`docs/work-plan.md`、`docs/work-progress.md` 和最新日报为准。

## 开始工作前

1. 查找并阅读项目根目录 `AGENTS.md`；若不存在，读取可用的协作说明。
2. 按项目规则阅读工程总览、工作计划、工作进度和最新日报。
3. 检查 `git status`、目标任务依赖、验收标准和现有未提交改动。
4. 找不到对应工作包时，先补充工作计划，不要隐式扩大范围。
5. 开始实质工作前，将工作包标记为 `开发中（0%）`；保留已有进度并写明负责人和开始日期。

## 工作期间

- 每完成一个可验证子项，更新进度、验证证据和下一步。
- 遵守项目的数据边界，不上传或提交 IPA、dSYM、混淆 map、凭证、私有源码及敏感日志。
- 让程序和测试产生事实；不要猜测来源归属、源码映射或产品结论。
- 缺失输入或工具记录为 `missing`、`unavailable` 或质量门禁失败。

### 方向确认超时

需要人工在多个方向中选择时，先给出选项、推荐项、推荐理由和等待开始时间。超过 10 分钟无回复，可采用推荐项继续，并在进度与日报记录等待起止时间、采用方向和关键假设。

该自动推进仅适用于方向/方案选择。删除或覆盖数据、外部写入/提交、权限或账号变更、安装软件、传输敏感数据等高风险操作，仍需明确授权。

## 工作结束前

1. 更新工作进度：已完成、未完成、验证、阻塞原因、解除条件和下一步。
2. 成功满足验收标准才标记 `已完成（100%）`；无法继续则标记 `阻塞（N%）`，不能只写“待处理”。
3. 更新当天中文日报；项目结构、依赖或运行方式变化时同步工程总览。
4. 运行相称的测试、CLI 检查或真实样本验证。
5. 检查 `git diff`、`git status` 和验证结果，只提交本次实际改动。
6. 创建 Git commit，提交信息必须使用“中文说明 / English summary”格式，例如：

   `文档：更新协作流程 / docs: update collaboration workflow`

7. 在进度文档和日报记录 commit hash。提交失败时记录失败原因和下一步，不得伪造已提交。

## 状态定义

- `未开始`：尚未实施。
- `开发中（N%）`：已开始并按已验证子项计算进度。
- `阻塞（N%）`：外部阻碍或必须等待状态；需记录原因、已完成工作、验证、解除条件和下一步。
- `已完成（100%）`：实现、验证、文档和 Git 交付均完成。
- `已取消`：记录取消原因。

## 项目适配

如果项目已有更严格的 `AGENTS.md` 或安全策略，以项目规则为准；本 Skill 不替代项目事实文档，也不扩大用户授权范围。
